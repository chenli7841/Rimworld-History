# Eastern Zhou: The Royal Court Moves East

The playable scenario is a vanilla `ScenarioDef` menu entry that selects the existing `HR_Scenario_EasternZhou_770BCE`; it does not duplicate that historical scenario Def. `HistoricalPlayableScenarioSetupDef` and `HistoricalStartingSuppliesDef` keep the start region, Zheng allegiance, population, initial technologies, supplies, and chapter end configurable in XML.

## Start configuration

- Historical start: astronomical year `-769` (770 BCE), month 1, day 1.
- Chapter end prompt: astronomical year `-739` (740 BCE); completion is optional and the save continues.
- Five vanilla generated player Pawns; names, ages, skills, and family relations are generated by RimWorld and are not hand-authored historical people.
- Starter supplies are configured in `Defs/HistoricalStartingSuppliesDefs/EasternZhou_770BCE.xml`. A custom vanilla scenario part creates each stack, split at the ThingDef stack limit.
- The chosen starting tile is associated with `HR_Region_ZhengHeartland` only in the saved PrototypeWorld mapping. It does not locate the player on a reconstructed map of ancient China.
- Zheng political state and `HR_Community_Player_001` come from the existing `HistoricalPoliticalSetupDef`, not from hardcoded political initialization.

## Initialization

After the vanilla scenario has generated its map and pawns, `HistoricalEasternZhouScenarioStartupGameComponent` matches the selected scenario name and calls `HistoricalEasternZhouScenarioInitializer`. The initializer validates the setup, asks the shared scenario manager to initialize the clock, politics, reveal state, event scheduler, genealogy, technology, culture, rituals and relics, maps the starting tile to the configured prototype region, adopts configured starting technologies, registers generated colonists in genealogy, links the family vessel relic, then records scenario progress. It is retryable and idempotent for pawn registration and relic linking, but the shared historical manager does not provide a cross-module rollback if a late initialization step fails. Such a failure is logged; it should be treated as a broken new game until runtime failure-path testing is complete.

## Play and handoff

The **Eastern Zhou** main tab displays the historical date, configured region, political allegiance, population, family count, revealed region count and chapter state. At or after the chapter end, the player may mark the chapter complete, export through `HistoricalLegacyExporter`, and keep playing. The exporter uses HR-010's versioned archive format and excludes map, vanilla faction control, buildings, inventory and unfinished tasks.

The bundled event list contains the 771 BCE crisis and 770 BCE eastward move as initial chronicle background, without replaying either action, plus a year-only scheduled Zheng succession entry for 743 BCE. The latter follows one recent scholarly reconstruction and is marked disputed; see its source note in the event language data. No month or day is invented. The event engine does not currently model a player-facing political demand, and the development-only Hedong unlock is not a playable progression event.

## Current scope and verification

The start uses vanilla rice, meals, construction materials, herbal medicine and bows plus the mod's clay, hemp fiber, copper/tin ore and speculative family vessel. This is a gameplay supply abstraction; it is not a sourced reconstruction of household inventories. A dedicated millet/foxtail crop is absent, hemp is an abstract fiber resource rather than a dedicated crop, and the current technology filter does not block every vanilla crop, raid, quest reward or third-party item route. Starting Pawn ages/skills are not constrained. Dynamic local incidents, negotiated demands, political change notices, automatic legacy migration history and a real China world map are not implemented by this integration.

The code compiles against the installed RimWorld 1.6 managed assemblies. XML well-formedness and API signatures can be checked locally, but only launching RimWorld with Biotech and starting/saving/reloading this scenario can validate Def loading, menu selection, map generation, stack spawning, Scribe round trips and UI behavior. Do not describe the chapter as fully runtime-verified until that pass is done.
